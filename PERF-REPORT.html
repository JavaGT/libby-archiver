TL;DR

Scope. Trial 2 of the continuous performance campaign, on top of trial-1-optimized main (fc670da). Four lanes across two waves: interface startup, decode CPU, download orchestration, RAM/storage — every change measured on this machine, every rejection documented with the numbers that killed it.

What improved. Every CLI invocation now starts at the bare-node floor (33.2→24.5 ms) via lazy per-command loading. Manifest hashing no longer pumps a fresh buffered stream per file: each of 8 workers reuses one 1 MiB buffer over an explicit pread loop — 51.6→32.2 ms on a 50 MB many-file tree (−38%), 272.2→147.5 ms at 200 MB (−46%), and −20% (20.71→16.47 ms) on a single 50 MB blob, outputs byte-identical everywhere.

What was measured and left alone. archive --all loan pipelining (saves exactly (N−1)×setup: 1.24× on a fast-download sim, only 2.2% on a 4-loan local e2e — single-digit % of real walls; a round-1 cross-loan corruption bug found in hostile review stands as the complexity tax; code preserved, not adopted). cfc1’s u32 swap (1.60× isolated, ~1% e2e — the 19 ms bench headline was a random-bytes utf8 artifact; realistic pages decode in 3.4 ms). Manifest hwm/worker knobs (both neutral-to-worse). EPUB assembly RAM is already within ~12 MB of the theory floor (transient allocator churn, not retention). Cover buffering and sidecar JSON format: below the worth-it bar.

T2-W1B

cfc1 page-blob decode — word-at-a-time quad swap

measured, rejected library (src/read.mjs)

Built and verified a u32 word-trick swap (view+shift/mask, plus 3 other variants) with byte-identical output on 144 adversarial fixtures (terminators at every offset, pairs gap 0..7, lengths incl. n%4!=0, U+2029 fallback path — the harness even caught a wrong-top-byte bug in the first draft before timing). Verdict: the isolated swap loop runs 1.60x faster (0.533→0.334 ms on 2.8 MB), but the swap is ~3% of the decode pipeline, so end-to-end the best variant manages only 1.01x (random blob) / 1.08x (realistic XHTML) — far under the 15% bar. Not adopted; src/read.mjs untouched; the 6-line change is documented as adopted-ready.

archive --all loan pipelining + read-path manifest pre-hash

measured, rejected orchestration (bin/libby.mjs, src/archive*.mjs, src/pool.mjs)

(1) Loan pipelining: archiveAudiobook/archiveReadable split into prepareX (claim folder + open loan + decode openbook — REST round trips) and finishX (downloads + assembly); archiveLoanQueue in bin keeps exactly ONE next-loan setup in flight during the active loan’s downloads. Prefetched logs buffer and replay in loan order (transcript-equality test), a failed prefetch surfaces as that loan’s FAILED line, whoa still exits 3, and the composed single-loan exports are preserved for the library API. (2) Read-path pre-hash: page bodies, assets, and the cover are sha256-hashed as they are written and fed to writeManifest’s known map alongside the EPUB digest, so the integrity pass re-reads only small sidecars; resume stays correct because only files written this run get entries.

T2-W3

EPUB-only readable archives (owner decision, lossless)

merged library storage (src/archive-read.mjs)

Readable archives no longer keep loose pages/, assets/, or cover.jpg — the assembled EPUB is the archive’s single copy of the content. During the run, payloads stage in a per-run temp dir (os.tmpdir) so the disk-backed entry thunks are preserved: whole-book residency stays out of memory exactly as W16 designed, and the staging dir is deleted in a finally after assembly (invisible to the manifest walk; a crash mid-run can only orphan it in OS tmp, never inside the archive). Losslessness is pinned by e2e: assets and the cover are byte-identical inside the EPUB; each page’s decoded body is embedded verbatim inside the standards-required XHTML shell (wrapPage = fixed prefix + body + suffix — nothing removed, recoverable by unwrapping; the test pins the exact template so any change is a conscious decision). README.txt/README.md document the new layout.

readable archive folder (sim e2e fixture)17319 bytes, 13→9 files11555 bytes, 13→9 files (33% less, 1.5×)

Tradeoffs / risks:

  • content inspection now needs an unzip (documented in README.txt); loose pages were a convenience, not a distinct artifact
  • page bodies are verbatim-but-wrapped inside the EPUB (raw-body recovery is deterministic unwrapping, not a file copy) — the byte-identical loose copy is gone by design
  • a kill mid-run can orphan a staging dir in OS tmp (never in the archive); there was no page resume logic before, so no capability is lost
  • RAM unchanged by design (staging preserves the thunk mechanism; ram-thunk tests pin it); W2C’s read-path pre-hash would have been partly obsoleted, but that bundle was already declined
  • audiobooks untouched: MP3 parts stay loose (no container holds them)
