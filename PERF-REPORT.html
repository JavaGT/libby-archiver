TL;DR

All waves are integrated on branch perf-trial-20260906-030748 (hub). main is untouched. 52/52 tests pass (28 at baseline), and every optimization is guarded by a regression or tradeoff-pinning test.

The library's biggest cost was the dependency-free EPUB zip writer: a pure-JS CRC32 loop (Node ships a native one — 70× faster), deflate level 9 applied to JPEG scans that compress 0% at any level, and a final whole-archive buffer copy. Fixing all three took EPUB assembly of a 13 MB magazine from ~189 ms to ~7 ms and cut peak memory 26%, with output marginally smaller than baseline.

The interface's biggest cost was serial round trips: every REST call paid a fresh TLS handshake (no keep-alive), audiobook parts downloaded one at a time, and a magazine's pages/assets were fetched one at a time — a 300-page magazine spent minutes waiting on the network. Measured against a local latency-injecting TLS server: connection reuse halved a 30-request loopback run (each saved handshake is worth 50–150 ms against the real OverDrive hosts), and bounded 4-way concurrency turned 120 × 25 ms requests from 3.2 s into 0.83 s (3.84×).

One candidate was measured and rejected: lazy-loading CLI commands (≤9 ms ceiling, invisible next to process spawn). It stays recorded so nobody re-litigates it.

Streaming EPUB writer (peak RAM)

New writeZip/writeEpub stream the archive to disk entry-by-entry (atomic .part + rename) instead of materializing the whole EPUB in memory — peak moves from O(archive) to O(largest entry). zip()/buildEpub stay with byte-identical output (pinned by test); archiveReadable now writes via writeEpub; entriesFor/writeZip/writeEpub are exported from the library index.

W17

Hash-once integrity pass

merged library · CPU + speed

downloadPart already computes each part’s sha256 while streaming, and archive.mjs was throwing it away — so writeManifest re-read the entire book to hash what had just been hashed. Part digests are now carried into writeManifest(dir, { known }), which trusts exact digests for matching files and only re-reads content nobody hashed (sidecars, cover, README).

metricbeforeafter
integrity pass, 50 MB archive, digests known22.8 ms0.28 ms (99% less, 81.43×)

Tradeoffs / risks:

  • Known digests are trusted, not re-verified (re-verifying would defeat the purpose); a streaming writer bug would surface as a bad manifest — the e2e suite validates every manifest line against file contents to police exactly this
  • Skipped (already-present) parts have no digest and are re-hashed as before — correct, since their bytes were not observed this run
  • Warm-cache M4 numbers; on cold caches the win is a full re-read of the book avoided

W23

Loop implementation showdown (cfc1, descramble)

merged library · CPU

Alternative implementations raced against the surviving hand-rolled loops, winners adopted behind a cheap pure-ASCII gate (Buffer.byteLength(s,utf8)===s.length): cfc1 swaps bytes in a latin1 buffer with an indexOf pre-scan (1.6× on a 2.8 MB blob); descramble shifts latin1 bytes in place (4.3–6.5× across key shapes) with a u16/fromCharCode-stride general fallback.
